# 业务活动与预算下达（仿制度）

> 模拟流程说明，非生产原文。不收录内网地址、真实姓名和库表名。

## 谁用、怎么区分

使用方包括省公司（信息技术与数据部门、创新院、厂商）和地市。系统用区域标记区分：省公司、创新院、各地市。

- 省公司：先有业务活动，再下任务订单。业务活动带年份。由预算下达生成。
- 地市：先有任务订单（采购供应链同步过来），再由定时任务生成业务活动。地市业务活动没有年份概念。
- 创新院、信息技术与数据部门在预算需求、业务外包上各有独立报表页；登录后按账号所属部门分流。

业务活动金额 = 预算分配金额 + 调整金额。若要失效一条活动，走逻辑删除，不物理抹掉。

## 状态

- 待补充信息
- 执行中
- 已关闭

省公司活动一般从执行中用起（下达后已补齐）。创新院、地市会经过待补充信息。

关闭：该活动下上一年的日常考核、工时核算都结束后，系统给项目负责人一条确认待办；点击确认后关闭。一个月未操作，系统自动改为已关闭。

## 预算两条路径

老路径（创新院一类）：管理员按模板导入各部门预算，生成业务活动后先下达为「待补充信息」，业务侧补完扩展信息再进入执行中。

新路径（信息技术与数据部门一类）：导入模板已包含活动补充字段。下达时校验必填（含补充字段）是否都有值，缺则提示「某活动某字段为空，请补充后再下达」。通过后直接进入执行中，跳过补充环节，由管理员接着关联合同。

三级经理按预算里的科室自动带出，不靠管理员逐条手填。导入时校验科室、厂商名称、金额（含上下半年合计）。已存在的同年活动按最新导入覆盖。

## 角色

常用角色：三级经理、项目负责人、核算管理员、安全管理员、外包管理员、厂商负责人、预算管理员。

打开活动时，创新院和地市由当前登录人指定对应处理人。更换项目负责人时，该人员名下未完成的业务外包待办转到新人。
